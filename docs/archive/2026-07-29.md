# 2026-07-29 — Custom 7I97T PktUART bitfile for head absolute-encoder (PSO) read

Goal: reboot-surviving **absolute homing** of the head **A/C** Yaskawa axes (26-bit
battery-backed absolute encoders, no home switch) by reading the drive's **PSO** absolute
serial stream (9600 7E1 ASCII) once at boot. This needs a UART receiver on the Mesa stack.

## The constraint (recap)
The 7I85's four encoder inputs are all **2:1 hardware-muxed** — useless for a continuous
UART (both head IDX pins map to the same FPGA I/O 50). The **only free non-muxed RS-422
receiver** on the whole stack is the 7I85 sserial **RXData1 = FPGA I/O 34 = TB1-19/20**.
Both drives' PSO are already wired to that pin through the **R4 DPDT mux** (`docs/tracing/relays.md`
→ R4; landed 2026-07-28). Earlier misstep, now corrected: PSO had first been aimed at the
IDX terminals — dead end (muxed, shared I/O 50). Only TB1-19/20 works.

## What was done — built + flashed a PktUART bitfile
Stock Mesa **7i97t_7i85sd** bitfile + a **hostmot2 PktUART on I/O 34 (RX) / 35 (TX)**.

- Efinity is x86-only (won't build on ned's Pi 5). Installed **Efinity 2026.1** on the
  Windows box **sleight** (`tzuohann@192.168.68.119` LAN / `100.99.61.59` Tailscale) over
  SSH, silent MSI, and drove the build there via `efx_run.bat ... --flow compile`.
- Source edits (3 files, vs stock `source/7i97t-hm2.zip`) — see
  `firmware/7i97t/hostmot2/pktuart_build/BUILD_NOTES.md`:
  1. `PIN_7I97_7I85SD_51.vhd`: 2 `NullTag` module rows → `PktUARTRTag`+`PktUARTTTag`;
     I/O 34/35 sserial RXData1/TXData1 → `PktURDataPin`/`PktUTDataPin`. (Count auto-derives:
     `PktUARTs := NumberOfModules(ModuleID, PktUARTRTag)` = 1.)
  2. `TopEthernet16HostMot2_efx.vhd`: active pinout `PIN_7I97D_51` → `PIN_7I97_7I85SD_51`
     (the stock top was building the bare-7I97 pinout — my edit would have been a no-op
     otherwise; caught it before the build).
  3. `seveni97t.xml`: P&R seed 3 → 7 (the annotated good seed; stock seed 3 = last run failed).
- Build: all stages **PASS** (map / interface / pnr / pgm / export_bitstream). Output
  `outflow/seveni97t.hex.bin` = **678650 bytes** — exactly the Mesa flash-bin size.

## Flash + verify (on the Pi, estop in, drives unarmed)
- `mesaflash --write` (verified OK) + `--reload`. `--readhmid`:
  **`PktUARTRX` ×1 + `PktUARTTX` ×1 on I/O 34/35**; every other module intact (DPLL,
  WatchDog, IOPort×3, MuxedQCount×10, SSerial×1 = 7I84, StepGen×4, PWM×6, SSR, InMux, LED).
- Temporary `halrun` load with `num_pktuarts=1`: driver logged
  **`created PktUART Interface function hm2_7i97.0.pktuart.0`** — no version rejection,
  clean exit, RT left unloaded. So LinuxCNC sees it.
- `ned.hal` hm2_eth config now carries `num_pktuarts=1`.
- Rollback path preserved: stock `7i97t_7i85sd.bin` + hardware `7i97t_16m_fallback.bin`.
