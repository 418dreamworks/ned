# 2026-07-29 — Custom 7I97T PktUART bitfile for head absolute-encoder (PSO) read

Goal: reboot-surviving **absolute homing** of the head **A/C** Yaskawa axes (26-bit
battery-backed absolute encoders, no home switch) by reading the drive's **PSO** absolute
serial stream (9600 7E1 ASCII) once at boot. This needs a UART receiver on the Mesa stack.

## The constraint (recap)
The 7I85's four encoder inputs are all **2:1 hardware-muxed** — useless for a continuous
UART (both head IDX pins map to the same FPGA I/O 50). The **only free non-muxed RS-422
receiver** on the whole stack is the 7I85 sserial **RXData1 = FPGA I/O 34 = TB1-19/20**.
Both drives' PSO are already wired to that pin through the **R4 DPDT mux** (`docs/tracing/relays.md`
→ R4; landed 2026-07-28). Earlier misstep, now corrected: PSO had first been aimed at the
IDX terminals — dead end (muxed, shared I/O 50). Only TB1-19/20 works.

## What was done — built + flashed a PktUART bitfile
Stock Mesa **7i97t_7i85sd** bitfile + a **hostmot2 PktUART on I/O 34 (RX) / 35 (TX)**.

- Efinity is x86-only (won't build on ned's Pi 5). Installed **Efinity 2026.1** on the
  Windows box **sleight** (`tzuohann@192.168.68.119` LAN / `100.99.61.59` Tailscale) over
  SSH, silent MSI, and drove the build there via `efx_run.bat ... --flow compile`.
- Source edits (3 files, vs stock `source/7i97t-hm2.zip`) — see
  `firmware/7i97t/hostmot2/pktuart_build/BUILD_NOTES.md`:
  1. `PIN_7I97_7I85SD_51.vhd`: 2 `NullTag` module rows → `PktUARTRTag`+`PktUARTTTag`;
     I/O 34/35 sserial RXData1/TXData1 → `PktURDataPin`/`PktUTDataPin`. (Count auto-derives:
     `PktUARTs := NumberOfModules(ModuleID, PktUARTRTag)` = 1.)
  2. `TopEthernet16HostMot2_efx.vhd`: active pinout `PIN_7I97D_51` → `PIN_7I97_7I85SD_51`
     (the stock top was building the bare-7I97 pinout — my edit would have been a no-op
     otherwise; caught it before the build).
  3. `seveni97t.xml`: P&R seed 3 → 7 (the annotated good seed; stock seed 3 = last run failed).
- Build: all stages **PASS** (map / interface / pnr / pgm / export_bitstream). Output
  `outflow/seveni97t.hex.bin` = **678650 bytes** — exactly the Mesa flash-bin size.

## Flash + verify (on the Pi, estop in, drives unarmed)
- `mesaflash --write` (verified OK) + `--reload`. `--readhmid`:
  **`PktUARTRX` ×1 + `PktUARTTX` ×1 on I/O 34/35**; every other module intact (DPLL,
  WatchDog, IOPort×3, MuxedQCount×10, SSerial×1 = 7I84, StepGen×4, PWM×6, SSR, InMux, LED).

- `ned.hal` hm2_eth config now carries `num_pktuarts=1`.
- Rollback path preserved: stock `7i97t_7i85sd.bin` + hardware `7i97t_16m_fallback.bin`.

# Air interlock made HARD + bench-script safety (same session)

User directive: "move nothing if air is not connected, including the spindle... air is a
prerequisite for the machine to work." Prior state: the bench scripts only **warned** on low
air, and ned.hal read `air-pressure-ok` but only **monitored** it — so move.sh happily jogged
A with the air disconnected.

Air sensor (already in the notes, `mesa_7i97t_wiring.md`): **TB5-7 → 7I97 IN12 → `*37`**
(Fagor X9-34 `/AIRFLT`) → signal `sig-air-pressure-ok` = `inmux.00.input-12`, **HIGH=OK**
(fail-safe: a broken sensor/wire reads not-TRUE → treated as no-air).

Changes:
- **ned.hal** — new `air.permit` and2: `iocontrol.0.emc-enable-in = sig-estop-released AND
  sig-air-pressure-ok`. Air loss now **E-STOPS** the machine, so nothing runs without air
  (no jog, no MDI, no spindle — one gate covers all). Restore air, reset e-stop to run.
- **tools/groundtruth/move.sh, solenoid.sh, pulsetest.sh** — air warning → **hard block** (refuse + tear
  down if `input-12 != TRUE`). **tools/groundtruth/mpgjog.sh** — blocks `arm`; dry-run still allowed
  (it drives nothing).
- **trash/tools/testall.sh** — fixed `awk: syntax error at or near 1` (line 88 `-$bs` became
  `--1` when `bs` flipped negative → awk read it as the decrement operator; parenthesized to
  `-($bs*$BRPS)`). NB: this script is retired to trash and still carries the OLD 200:1 head
  ratio (line 24) — head moves in it would be wrong; fix the ratio if it's ever un-trashed.

Verify (needs a LinuxCNC restart): with air disconnected the machine must refuse to leave
e-stop / enable; reconnect air → resets normally.

# PSO read attempt — reader works, drive silent (same session)

Built `tools/pso_sniff.comp`: a HAL component that configures `hm2_7i97.0.pktuart.0` at
**9600 baud** (raw 8-bit capture; PSO is 7E1 → mask `0x7f` for the ASCII char) and exposes
`total`/`rxbytes`/`frames`/`last-err` pins + dumps the first frames to dmesg. Bug found +
fixed along the way: storing `name = prefix` kept a **dangling pointer** (`prefix` isn't
persistent) → `receive` called `hm2_pktuart_read` with garbage → *"Can not find PktUART
instance"*. Must **copy** the name into per-instance storage.

Live test (halrun: board + pso_sniff, 5 s, **no motion**): the pktuart configures and reads
**cleanly (`last-err = 0`)** but **`total = 0` bytes, `0` frames** — the head drive is **not
emitting PSO right now**. The reader is proven; there is simply no data on the line. To get
bytes: drive control power on **and** either `Pn515=7` (continuous no-SEN stream) **or** catch
the **power-up burst** (Yaskawa default = absolute serial at power-up, then reverts — exactly
PCW's "serial at power-up" note; catching it means the sniffer must be live when the drive
powers on).

Caveat for the final design: `hm2_eth: ERROR: used llio->read in realtime task` — reading the
pktuart **every servo cycle** on the ETHERNET card is out-of-band (~120 µs/cycle, extra
packets). Fine for a once-at-boot PSO read; do **not** addf the reader to the fast servo
thread for continuous polling — read it from a slow/userspace context instead.

Also: exposing the head incremental encoders (`enc.08` = C, `enc.09` = A) needs
**`num_encoders=10`** in the hm2_eth config; ned.hal still has `num_encoders=6` (bump it as
part of task #10, the head-encoder-feedback wiring).
